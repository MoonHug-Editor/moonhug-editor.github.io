MoonHug Editor

An extensible editor for Odin projects.

A generic editor you extend with attributes, an engine plugin with scenes, components and rendering, and the plugins that build on it.

Early stage. APIs change often, there are bugs, and some features are not implemented yet. It is a good moment to contribute and shape how the editor grows. How to contribute

Three layers

The libs are packages that run nothing on their own. Two executables are built on them: the Editor, which you edit a project in, and the App, the project's own executable. Plugins are what the Editor and the App load.

1

Libs

Small packages, each imported on its own and only where it is used: core, log, serialization, assets, catalog, gfx, input, gizmos.

moonhug/libs/<name>
2

Editor

The generic editing application: windows, docking, menus, inspector, undo, project view, viewport, Simulate, console. It declares the extension points plugins fill and builds with no plugin installed.

moonhug/editor
3

Plugins

Packages a project adds or leaves out. They extend the Editor through attributes and build on the plugins they declare as dependencies.

plugins/<name> 
App      libs ── engine plugin ── other plugins ── the app package

Editor   libs ─┬ engine plugin ── other plugins ── the app package
               │    │                 │                    │
               │    └ engine/editor/  └ <plugin>/editor/   └ app/editor/
               └ editor──┴────────────────┴───────────────────┘

Imports go one way: right to left along a line and up a branch. The Editor runs the same plugin code the App does and adds each plugin's editor/ part. The editor never imports a plugin. It reaches one only through what the plugin registered, so with no plugin installed it still builds and runs.

Plugins

A plugin is an Odin package with a manifest and a few special folders. A project enables the plugins it needs. Two of them have a special role.

special role

Engine

The plugin that brings scenes, transforms, components, rendering, materials, meshes, the fixed tick and the App's frame loop. Its editor part adds the scene view, the hierarchy and the game view. Other plugins build on it, and a project uses it or not.

plugins/engine
special role

App

A runnable plugin: its root declares main, and it is built as its own executable. A game is one kind of app.

plugins/app

In the repo

animation

Clip playback through a graph of source, blend and output nodes, and an Animation component on a transform hierarchy.

audio

SDL3_mixer playback, imported clips with baked gain, AudioSource, one-shots and spatial sound.

essentials

Starter assets: primitive meshes, materials, shaders, textures and the default render pipeline.

input_actions

Action maps with bindings per device, a priority stack of maps, and per-frame and per-tick action values.

mhgui

The UI canvas: images, layout groups and their editor tooling.

text

Signed-distance-field text for the UI canvas, with fonts baked to atlases at import.

sprites

SpriteRenderer with a texture cache, sorting and scene view rendering.

particles

CPU particle systems with curve and gradient modules over lifetime.

physics2d

Rigidbodies, colliders, physics materials and layers on Box2D.

physics3d

Rigidbodies, colliders, mesh colliders with convex decomposition, physics materials and layers on Box3D.

shadergraph

Node-based surface shaders compiled to the engine's surface template.

postfx

Post effects as render pipeline steps: bloom, tonemap operators, FXAA.

tween

Tween trees authored in component fields and played as pooled live nodes.

sequencer

Timelines as prefabs: a director on the root, tracks and clips as its children.

node_graph

A pan and zoom node canvas that other plugins draw their graphs on.

Attributes in, code out

Before anything compiles, the prebuild reads the attributes in every installed package and writes the glue: dispatchers, registrations, the editor's windows and menus, the reference docs. A plugin can ship generators of its own in its gen/ folder.

plugins/my_game/projectile.odin
@(component={menu="Demo/Projectile"})
@(typ_guid={guid = "7f5e6f68-938f-467f-993e-4d92adb25233"})
Projectile :: struct {
    using base: engine.CompData `inspect:"-"`,
    speed: f32,
}

@(update={order=2})
projectile_tick :: proc(dt: f32) { /* ... */ }
plugins/my_game/editor/my_tool.odin
@(menu_item={path="Window/My Tool"})
my_tool_open :: proc() { /* ... */ }
prebuild →↓
  • @(component) Projectile is in Add Component under Demo, and the inspector draws its fields.
  • @(typ_guid) The type has a stable id, so scenes save and load it.
  • @(update) projectile_tick runs every frame of the game, sorted by its order.
  • @(menu_item) My Tool is in the Window menu.

Every attribute is declared in the package it extends, and the prebuild stops on an attribute it does not know, with the closest known name as a hint.

Get started

  1. Install Odin and SDL3. On macOS:

    brew install sdl3

  2. Clone the repo with its submodules:

    git clone --recursive https://github.com/MoonHug-Editor/moonhug.git
cd moonhug

  3. Set up once. This repairs the plugin links and builds the vendored C libraries:

    odin run tools/mh -- setup

  4. Run. This generates code, compiles the editor and launches it:

    odin run tools/mh -- run
